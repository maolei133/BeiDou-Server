# 日志系统使用说明文档

## 1. 系统概述

新的日志系统是一个高性能、模块化的日志记录和查询系统，专为游戏服务器设计。它支持记录客户端和角色的详细信息，并提供强大的查询功能。

## 2. 核心功能

### 2.1 日志分类管理
系统采用两级分类体系：
- **大类(Major)**: 定义日志的主要类型，如玩家(player)、物品(item)、经济(economy)等
- **小类(Minor)**: 定义大类下的具体子类型，如玩家登录(login)、登出(logout)等

### 2.2 用户信息记录
自动记录以下用户相关信息：
- IP地址
- MAC地址（最后一个）
- 硬件ID(HWID)
- 账号和账号ID
- 角色名和角色ID
- 地图名称和地图ID

### 2.3 数据去重和缓存
系统自动对用户信息进行去重处理，并缓存在内存中，支持前端快速筛选。用户数据会定期自动写入userdata.json文件。

### 2.4 高性能异步写入
采用单线程异步写入机制，避免阻塞主线程，确保高性能。日志文件按日期命名并自动清理过期文件。

### 2.5 前端查询界面
提供Web界面用于查询和筛选日志，支持多条件组合查询。

## 3. 使用方法

### 3.1 记录日志

#### 3.1.1 基础用法
```java
// 记录玩家登录日志
ModuleLogger.logPlayerLogin(client, chr);

// 记录玩家登出日志
ModuleLogger.logPlayerLogout(client, chr);

// 记录物品获得日志
ModuleLogger.logItemObtain(client, chr, "红药水", 50, "怪物掉落");

// 记录交易日志
ModuleLogger.logTrade(client, chr, "其他玩家", "红药水", 10, 1000);

// 记录技能使用日志
ModuleLogger.logSkillUse(client, chr, "火球术", 1001001, 5);

// 记录怪物击杀日志
ModuleLogger.logMonsterKill(client, chr, "绿蜗牛", 100100, 100000000);

// 记录GM命令日志
ModuleLogger.logGMCommand(client, chr, "!levelup", new String[]{"10"});

// 记录聊天日志
ModuleLogger.logChat(client, chr, "party", "大家好", 100000000);
```

#### 3.1.2 自定义日志记录
```java
// 创建自定义模块日志记录器
ModuleLogger logger = new ModuleLogger(LogCategoryDefinition.Major.PLAYER, LogCategoryDefinition.Minor.LEVEL_UP);

// 记录单个字段
logger.log(client, chr, "level", 10);

// 记录多个字段
logger.log(client, chr, new String[]{"level", "job"}, new Object[]{10, "战士"});

// 记录Map形式的字段
Map<String, Object> data = new HashMap<>();
data.put("level", 10);
data.put("job", "战士");
data.put("map", "射手村");
logger.log(client, chr, data);
```

#### 3.1.3 内置辅助系统日志记录
```java
// 记录内置辅助系统日志
CheatSystemLogger.logCheatSystem(chr, "插件系统初始化完成");

// 记录内置辅助插件激活日志
CheatSystemLogger.logPluginActivation(chr, "ItemVacPlugin", "插件已激活");

// 记录内置辅助插件停用日志
CheatSystemLogger.logPluginDeactivation(chr, "ItemVacPlugin", "插件已停用");

// 记录内置辅助插件使用日志
CheatSystemLogger.logPluginUsage(chr, "ItemVacPlugin", "拾取了5个物品");
```

### 3.2 查询日志

#### 3.2.1 通过前端界面查询
1. 访问日志管理页面
2. 选择大类和小类
3. 设置筛选条件（日期范围、关键词、IP、MAC等）
4. 点击查询按钮查看结果

#### 3.2.2 通过API查询
```bash
# 查询日志
GET /api/logs/query?majorCategory=player&minorCategory=login&startDate=2023-01-01&endDate=2023-12-31&ip=127.0.0.1

# 获取所有大类
GET /api/logs/categories/major

# 获取指定大类下的所有小类
GET /api/logs/categories/minor?majorCategory=player

# 获取用户数据
GET /api/logs/userdata
```

## 4. 系统架构

### 4.1 核心类说明

#### 4.1.1 LogCategoryDefinition
日志分类定义类，统一管理所有日志的大类和小类。

#### 4.1.2 BaseLogEntry
基础日志实体类，包含用户基本信息。实现了用户数据的自动去重和缓存功能。

#### 4.1.3 BaseLogger
基础日志记录器，提供异步日志写入和用户数据缓存功能。支持按日期命名日志文件和自动清理过期日志。

#### 4.1.4 ModuleLogger
模块化日志记录器，支持不同功能模块的日志记录。提供多种便捷的日志记录方法。

#### 4.1.5 CheatSystemLogger
内置辅助系统专用日志记录器，继承自ModuleLogger，专门为内置辅助插件提供日志记录功能。

#### 4.1.6 LogQueryService
日志查询服务，提供日志文件查询功能。

#### 4.1.7 LogController
日志控制器，提供REST API接口。

### 4.2 数据存储结构
```
logs/
├── custom/
│   ├── player/
│   │   ├── login/
│   │   │   ├── 2023-01-01.log
│   │   │   └── 2023-01-02.log
│   │   └── logout/
│   └── .../
├── userdata.json
```

## 5. 性能优化建议

### 5.1 日志写入优化
- 使用异步写入避免阻塞主线程
- 合理设置线程池大小
- 批量写入减少I/O操作

### 5.2 日志查询优化
- 合理设计日志文件目录结构
- 使用索引提高查询效率
- 限制查询结果数量避免内存溢出

### 5.3 内存使用优化
- 定期清理过期缓存
- 合理设置缓存大小
- 使用对象池减少GC压力

## 6. 常见问题及解决方案

### 6.1 日志文件过大
**问题**: 日志文件增长过快，占用大量磁盘空间。
**解决方案**: 
- 系统默认保留10天内的日志，自动清理过期文件
- 压缩日志内容（目前已实现）
- 调整日志记录级别，减少不必要的日志

### 6.2 查询性能下降
**问题**: 日志数据量增大后查询变慢。
**解决方案**:
- 增加查询条件索引
- 优化查询算法
- 考虑使用专业日志存储系统（如ELK）

### 6.3 内存占用过高
**问题**: 系统运行时间长后内存占用持续增长。
**解决方案**:
- 检查是否有内存泄漏
- 调整缓存策略和大小
- 定期清理过期数据

### 7.2 添加新的日志记录方法

2. 确保方法参数合理，易于使用

2. 更新语言包文件支持新功能的文本显示
3. 必要时扩展后端API接口
