# 开发计划书

## 项目概述
本项目旨在重构org/gms/log日志系统，建立统一、高效、可扩展的日志管理机制。新系统需要支持模块化日志记录、高性能写入、统一数据结构、前端查询展示等功能。

## 需求分析
1. 分析现有org/gms/log日志系统，确定各功能作用
2. 生成类用来定义日志大类和小类
3. 生成基类记录client和character信息
4. 去重信息并写入userdata.json
5. 采用模块化设计
6. 模块日志拥有独立记录方法但调用基类写出方法
7. 数据结构采用JSON，每行一个独立JSON结构
8. 数据结构采用动态定义
9. 日志系统高效，支持高并发
10. 开发前端查询页面，支持基础筛选和模块筛选

## 技术选型
- 后端：Java
- 前端：Vue.js
- 数据格式：JSON
- 日志存储：文件系统
- 构建工具：Maven

## 4. 技术方案

### 4.1 数据结构设计

采用JSON格式存储日志，结构如下：
```json
{
  "t": "2023-01-01 10:00:00",
  "v": "1.0",
  "ip": "127.0.0.1",
  "mac": "00:11:22:33:44:55",
  "hwid": "ABC123DEF456",
  "acc": "testuser",
  "accId": 100001,
  "chr": "TestCharacter",
  "chrId": 200001,
  "wId": 0,
  "mId": 100000000,
  "customFields": {
    "level": 10,
    "map": "maple_island"
  },
  "mod": "player.login"
}
```

### 4.2 并发处理方案

使用线程池处理日志写入操作，避免阻塞主线程：
1. 创建固定大小的线程池
2. 日志记录请求放入队列
3. 线程池异步处理日志写入

### 4.3 去重与缓存方案

1. 使用内存中的HashSet存储已知信息，实现快速去重
2. 定期将去重数据写入userdata.json
3. 提供API接口供前端查询用户数据

## 6. 接口设计

### 6.1 后端接口

1. 查询用户数据接口
   - URL: /api/logs/userdata
   - 方法: GET
   - 返回: IP、MAC、HWID、账号、角色名等去重数据列表

2. 查询模块筛选字段接口
   - URL: /api/logs/module/fields
   - 方法: GET
   - 参数: module(模块名)
   - 返回: 该模块支持的筛选字段列表

### 6.2 前端组件

1. 基础筛选组件
   - IP、MAC、HWID、账号、账号ID、角色名、角色ID下拉选择
2. 模块筛选组件
   - 根据选择的小类动态显示对应的筛选字段
3. 日志显示组件
   - 表格形式展示日志内容
