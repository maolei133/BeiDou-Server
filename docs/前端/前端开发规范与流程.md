# gms-ui 前端开发规范与流程

本文档旨在为 `gms-ui` 项目提供统一的开发规范和流程指导，便于后续功能扩展和维护。

## 1. 前后端交互流程

`gms-ui` 采用标准的前后端分离架构，前端通过 RESTful API 与后端进行数据交互。

### 1.1 交互时序

1.  **用户操作**：用户在 Vue 组件（页面）中触发操作（如点击按钮、提交表单）。
2.  **调用 API**：组件调用 `src/api/` 目录下封装好的 API 函数。
3.  **请求拦截**：`src/api/interceptor.ts` 中的 Axios 请求拦截器自动添加 Token (`Authorization: Bearer ...`) 和 Request ID。
4.  **发送请求**：Axios 向后端发送 HTTP 请求。
5.  **后端处理**：后端处理请求并返回 JSON 数据。
6.  **响应拦截**：`src/api/interceptor.ts` 中的 Axios 响应拦截器处理响应：
    *   **成功 (Code 20000)**：返回 `data` 部分给调用者。
    *   **失败 (Code != 20000)**：弹出错误提示 (Message.error)，并抛出异常。
    *   **Token 过期 (Status 401)**：自动登出并跳转至登录页。
7.  **更新 UI**：组件接收到数据，更新响应式变量，视图自动刷新。

### 1.2 核心模块交互示例 (以账号列表为例)

1.  **定义 API (`src/api/account.ts`)**:
    ```typescript
    export function getAccountList(page: number, size: number, ...) {
      // 构建 URL 参数
      return axios.get<PageState>(url);
    }
    ```
2.  **定义类型 (`src/store/modules/account/types.ts`)**:
    ```typescript
    export interface AccountState { id: number; name?: string; ... }
    ```
3.  **组件调用 (`src/views/account/list/index.vue`)**:
    ```typescript
    import { getAccountList } from '@/api/account';
    
    const loadData = async () => {
      setLoading(true);
      try {
        const { data } = await getAccountList(page.value, size.value, ...);
        tableData.value = data.records; // 更新表格数据
        total.value = data.totalRow;    // 更新分页总数
      } finally {
        setLoading(false);
      }
    };
    ```

## 2. 具体开发规范

### 2.1 目录与文件命名
*   **目录**：使用 `kebab-case` (短横线连接)，如 `views/account-list`。
*   **Vue 组件**：使用 `PascalCase` (大驼峰) 或 `kebab-case`，建议统一为 `index.vue` 作为入口，子组件用 `PascalCase`，如 `AddForm.vue`。
*   **TS/JS 文件**：使用 `camelCase` (小驼峰)，如 `user.ts`, `stringUtils.ts`。
*   **API 文件**：与后端 Controller 或模块名保持一致，如 `account.ts` 对应后端 AccountController。

### 2.2 API 定义规范 (`src/api/`)
*   **引入 Axios**：统一使用 `import axios from 'axios';`。
*   **类型定义**：为请求参数和响应数据定义 TypeScript 接口 (Interface)。
    *   请求参数接口命名建议：`XxxForm`, `XxxQuery`, `XxxCondition`。
    *   响应数据接口命名建议：`XxxState`, `XxxResult`。
*   **函数命名**：使用 `动词+名词` 形式，如 `getAccountList`, `updateUser`, `deleteItem`。
*   **路径参数**：使用模板字符串拼接，如 `` `/account/v1/${id}` ``。

### 2.3 Vue 组件规范 (`src/views/`)
*   **Script Setup**：统一使用 `<script setup lang="ts">` 语法糖。
*   **Loading 状态**：使用 `src/hooks/loading.ts` 中的 `useLoading` 钩子管理加载状态。
    ```typescript
    const { loading, setLoading } = useLoading(false);
    ```
*   **国际化 (i18n)**：
    *   使用 `useI18n` 钩子。
    *   模板中使用 `$t('key')`。
    *   脚本中使用 `t('key')`。
    *   禁止在代码中硬编码中文文本。
*   **表单处理**：
    *   使用 `reactive` 定义表单数据对象。
    *   使用 `ref` 获取 Form 实例进行验证 (`validate()`)。
    *   新增/编辑弹窗建议封装为独立组件，通过 `defineExpose({ init })` 暴露初始化方法供父组件调用。

### 2.4 状态管理规范 (`src/store/`)
*   使用 Pinia (或 Vuex，视项目具体依赖而定，目前代码看似混用或过渡期，以 `store/modules` 结构为主)。
*   类型定义放在 `types.ts` 中。
*   尽量避免将所有状态都放入 Store，仅存放全局共享状态（如用户信息、权限、全局配置）。页面级状态应保留在组件内部。

### 2.5 工具类规范 (`src/utils/`)
*   **通用工具**：放入 `utils/` 根目录，如 `stringUtils.ts`。
*   **认证工具**：`auth.ts` 专门处理 Token 的存储、获取和清除。
*   **校验工具**：`isValidString` 等函数用于参数校验。

### 2.6 代码格式化规范 (Prettier)
项目强制使用 Prettier 进行代码格式化，请确保编辑器安装了 Prettier 插件并开启了保存自动格式化。
具体配置参考 `.prettierrc.js`：
*   **缩进**：2 个空格 (`tabWidth: 2`)
*   **分号**：行尾必须加分号 (`semi: true`)
*   **行宽**：80 字符 (`printWidth: 80`)
*   **引号**：使用单引号 (`singleQuote: true`)
*   **对象属性引号**：仅在必要时添加 (`quoteProps: 'consistent'`)
*   **HTML 空格敏感度**：严格模式 (`htmlWhitespaceSensitivity: 'strict'`)
*   **Vue 缩进**：`<script>` 和 `<style>` 标签内容缩进 (`vueIndentScriptAndStyle: true`)

## 3. 框架规范与最佳实践

### 3.1 UI 组件库 (Arco Design Vue)
*   项目使用 **Arco Design Vue** 作为 UI 框架。
*   **表格 (Table)**：
    *   使用 `<a-table>`。
    *   必须绑定 `row-key`。
    *   列定义使用 `<a-table-column>` 或 `columns` 属性。
    *   复杂内容（如标签、按钮）使用 `#cell="{ record }"` 插槽自定义。
*   **表单 (Form)**：
    *   使用 `<a-form>` 和 `<a-form-item>`。
    *   绑定 `model` 和 `rules`。
    *   使用 `validate-trigger="blur"` 优化验证体验。
*   **反馈 (Feedback)**：
    *   成功/失败提示使用 `Message.success()` / `Message.error()`。
    *   确认操作（如删除）使用 `<a-popconfirm>`。

### 3.2 响应式数据
*   **ref**：用于基本类型 (number, string, boolean) 或 替换整个对象/数组。
*   **reactive**：用于对象属性的深层响应，常用于表单数据对象。
*   **computed**：用于依赖其他响应式数据的计算属性。

### 3.3 路由与菜单
*   路由配置位于 `src/router/`。
*   菜单通常由后端动态返回 (`getMenuList` 接口) 或在前端路由元数据 (`meta`) 中配置。

### 3.4 扩展新功能步骤
1.  **后端**：确认后端 API 接口已就绪并测试通过。
2.  **API**：在 `src/api/` 下新建或修改对应的 `.ts` 文件，定义接口函数和类型。
3.  **Store (可选)**：如果需要全局状态，更新 `src/store/`。
4.  **View**：
    *   在 `src/views/` 下创建新目录。
    *   创建 `index.vue` (列表页) 和 `components/` (表单/详情页)。
    *   编写 UI 结构，绑定数据。
    *   调用 API 获取数据。
    *   添加交互逻辑 (搜索、分页、增删改)。
5.  **路由**：在 `src/router/` 中注册新页面。
6.  **国际化**：在 `src/locale/` 添加对应的翻译文本。

---
**注意**：在修改代码时，请保持与现有代码风格一致（Prettier/ESLint 配置）。

## 4. 前后端开发要求与注意事项

### 4.1 接口设计规范
*   **RESTful 风格**：遵循 RESTful 风格设计 API，使用 HTTP 动词 (GET, POST, PUT, DELETE) 表示操作类型。
*   **统一响应格式**：后端统一返回 JSON 格式，包含 `code` (状态码), `msg` (消息), `data` (数据)。
    ```json
    {
      "code": 20000,
      "msg": "success",
      "data": { ... }
    }
    ```
*   **参数校验**：后端必须对前端传递的参数进行校验，前端也应进行基本的格式校验。
*   **错误处理**：后端捕获异常并返回友好的错误信息，前端统一拦截并提示。
*   **特殊字段命名**：
    *   **智力属性**：前端统一使用 `int` 作为智力属性的字段名。
    *   **避免混淆**：禁止使用 `int_`、`intel` 等变体，以确保前后端数据映射的一致性。后端 DTO 应使用 `@JsonProperty("int")` 进行适配。

### 4.2 数据安全
*   **敏感信息脱敏**：后端返回用户信息时，应对密码、手机号等敏感信息进行脱敏处理。
*   **权限控制**：后端接口应进行权限校验，防止未授权访问。前端根据权限控制菜单和按钮的显示。
*   **防 SQL 注入**：后端使用 MyBatis 等框架时，注意防止 SQL 注入。

### 4.3 性能优化
*   **分页查询**：列表接口必须支持分页，避免一次性返回大量数据。
*   **按需加载**：前端路由懒加载，组件按需引入。
*   **缓存**：合理使用浏览器缓存和后端缓存 (Redis)。

### 4.4 代码质量
*   **注释**：关键逻辑和复杂算法必须添加注释。
*   **代码复用**：避免重复代码，提取公共组件和工具函数。
*   **类型安全**：前端尽量使用 TypeScript 的类型检查，后端使用强类型。

### 4.5 联调与测试
*   **Mock 数据**：前端开发阶段可使用 Mock 数据模拟后端接口。
*   **接口文档**：后端提供详细的接口文档 (Swagger/YApi)，方便前端查阅。
*   **联调测试**：前后端开发完成后，进行联调测试，确保功能正常。
