# 前端架构文档

## 1. 概述

`BeiDou-Server-Magical` 的前端管理界面 `gms-ui` 是一个基于 Vue 3 和 TypeScript 构建的单页面应用 (SPA)。它提供了一个直观的界面，用于管理游戏服务端的数据、配置和监控。

## 2. 技术选型

- **核心框架**: Vue 3 (Composition API)
- **编程语言**: TypeScript
- **构建工具**: Vite
- **状态管理**: Pinia
- **UI 组件库**: Arco Design Vue
- **HTTP 客户端**: Axios
- **路由**: Vue Router 4
- **代码规范**: ESLint, Prettier, Stylelint
- **其他**: `@vueuse/core`, Lodash, Day.js, ECharts

## 3. 架构分层

前端项目也遵循模块化和分层设计原则，以提高代码的可维护性和可扩展性。

```
+---------------------+
|        Views        |  (页面组件: 组合组件, 业务逻辑)
+---------------------+
        |
        v
+---------------------+
|     Components      |  (通用组件: 可复用 UI 元素)
+---------------------+
        |
        v
+---------------------+
|        Store        |  (状态管理: 全局状态, 业务数据)
+---------------------+
        |
        v
+---------------------+
|         API         |  (接口封装: 与后端交互)
+---------------------+
```

### 3.1. Views (页面层)

- **职责**: 承载具体的业务页面，组合各种组件和数据，实现页面级的业务逻辑。
- **实现**: 位于 `src/views/` 目录下，每个页面通常是一个 `.vue` 文件。
- **规范**:
    - 使用 Vue 3 的 Composition API 编写逻辑。
    - 负责调用 `Store` 中的 actions 来获取或修改数据。
    - 协调多个组件的交互。
    - 处理页面级的路由参数和生命周期。

### 3.2. Components (组件层)

- **职责**: 提供可复用的 UI 元素。
- **实现**: 位于 `src/components/` 目录下，每个组件通常是一个 `.vue` 文件。
- **规范**:
    - 遵循单一职责原则，功能明确。
    - 通过 `props` 接收数据，通过 `emits` 触发事件与父组件通信。
    - 尽量保持无状态或只包含少量内部状态。
    - 优先使用 Arco Design Vue 提供的基础组件。

### 3.3. Store (状态管理层)

- **职责**: 管理全局应用状态和业务数据。
- **实现**: 使用 Pinia，位于 `src/store/` 目录下，按业务模块划分。
- **规范**:
    - 每个模块 (如 `user`, `settings`, `map`) 对应一个 Pinia store。
    - `state` 定义数据，`getters` 计算派生状态，`actions` 封装异步操作和业务逻辑。
    - 页面和组件通过 `useStore()` 访问状态和调用 actions。

### 3.4. API (接口封装层)

- **职责**: 封装所有与后端交互的 HTTP 请求。
- **实现**: 位于 `src/api/` 目录下，按业务模块划分文件。
- **规范**:
    - 使用 Axios 实例 (`src/utils/request.ts`) 发送请求。
    - 每个函数对应一个后端 API 接口。
    - 包含完整的 JSDoc 注释，描述接口功能、参数和返回值。
    - 统一处理请求和响应的错误。

### 3.5. Router (路由层)

- **职责**: 管理应用的页面导航。
- **实现**: 使用 Vue Router 4，配置位于 `src/router/` 目录下。
- **规范**:
    - 定义应用的路由表，包括路径、组件、元信息 (`meta`)。
    - 实现路由守卫 (Navigation Guards) 进行权限验证、登录状态检查等。
    - 支持动态路由和嵌套路由。

### 3.6. Utils (工具函数层)

- **职责**: 提供项目通用的工具函数。
- **实现**: 位于 `src/utils/` 目录下。
- **规范**:
    - 包含日期格式化、字符串处理、HTTP 请求封装、权限判断等通用功能。
    - 避免重复造轮子，优先使用现有工具函数。

## 4. 核心概念

### 4.1. TypeScript

- **职责**: 提供静态类型检查，提高代码质量和可维护性。
- **规范**:
    - 所有 `.ts` 和 `.vue` 文件中的 `<script setup>` 块都应使用 TypeScript。
    - 明确定义接口 (interface) 和类型 (type)。

### 4.2. Arco Design Vue

- **职责**: 提供一套高质量的 UI 组件，确保界面风格统一和开发效率。
- **规范**:
    - 优先使用 Arco Design Vue 提供的组件。
    - 遵循其设计规范和使用方式。
    - 对于需要定制的组件，应在 `src/components/` 目录下进行封装和扩展。

### 4.3. Vite 构建

- **职责**: 提供快速的开发服务器和高效的生产构建。
- **配置**: 位于 `config/vite.config.dev.ts` 和 `config/vite.config.prod.ts`。
- **优势**: 基于 ESM 的开发模式，热模块替换 (HMR) 速度快。

## 5. 开发工作流

1.  **需求分析**: 明确页面功能、交互和数据流。
2.  **组件设计**: 识别可复用组件，并使用 Arco Design Vue 进行实现。
3.  **状态管理**: 定义 Pinia store，包括 state, getters, actions。
4.  **API 交互**: 在 `src/api/` 中封装后端接口。
5.  **页面开发**: 在 `src/views/` 中组合组件，调用 store 和 api。
6.  **路由配置**: 在 `src/router/` 中配置路由和权限。
7.  **代码审查**: 遵循 ESLint, Prettier, Stylelint 规范进行代码审查。

通过以上架构和规范，`gms-ui` 旨在提供一个结构清晰、易于开发和维护的前端管理界面。
