# 物品找回系统设计文档

## 1. 概述

### 1.1 背景
玩家在游戏过程中，可能会因误操作（如手滑出售、丢弃）而损失重要物品。为了提升玩家体验，减少客诉压力，需要建立一套官方的物品找回机制。

### 1.2 目标
1.  **玩家自助找回**：提供NPC交互界面，允许玩家在一定时限内、支付少量手续费找回近期出售或丢弃的“有价值”物品。
2.  **GM后台支持**：提供Web后台功能，允许管理员查询玩家的物品处理记录，并能无视时限、无偿地为玩家恢复物品。
3.  **安全可控**：找回过程必须记录日志，且系统需有明确的价值判断，避免玩家利用该系统存储或复制物品。
4.  **自动化管理**：系统能自动清理过期的找回记录，保持数据库健康。

## 2. 核心设计

本系统依赖于“物品流转溯源系统”的基础，特别是 `item_recovery_logs` 表。

### 2.1 数据库核心 (`item_recovery_logs` 表)
此表是物品找回系统的“回收站”。

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | BIGINT | 主键 |
| `character_id` | INT | 所属角色ID |
| `uid` | BIGINT | 物品唯一ID |
| `item_id` | INT | 物品模板ID |
| `item_data` | JSON | 物品被处理时的完整属性快照 |
| `disposal_type`| VARCHAR(16)| **[枚举管理]** 处理方式，由 `ItemRecoveryService.DisposalType` 枚举定义。包括: `SELL`, `DROP`, `DELETE`, `SCROLL_FAIL`, `MAKER_FAIL`, `QUEST` |
| `disposal_time`| BIGINT | 处理时间戳 |
| `recovery_deadline`| BIGINT | 可找回的截止时间戳 |
| `status` | VARCHAR(16)| **[枚举管理]** 记录状态，由 `ItemRecoveryService.RecoveryStatus` 枚举定义。包括: `PENDING`, `RECOVERABLE`, `RECOVERED`, `EXPIRED`, `RECOVERED_BY_GM` |

### 2.2 价值判断 (`isValuableForRecovery`)
此函数是防止滥用的关键，它定义了哪些物品值得被记录到找回系统。判断标准与溯源系统完全一致。

*   **统一判断入口**: `InventoryManipulator.isValuableForRecovery(Item item)`
*   **V1规则 (硬编码)**:
    *   **装备 (`EQUIP`)**: 高级装备 (>=120级)、已强化或属性高于白板。
    *   **消耗品 (`USE`)**: 记录卷轴、技能书等，排除普通药水。
    *   **其他 (`ETC`)**: 记录任务物品、稀有材料等。
    *   **设置 (`SETUP`) / 现金 (`CASH`)**: 默认全部记录。

> **[V2 重要警告] 配置共享与影响**
>
> 随着“物品流转溯源系统”V2版本的上线，`isValuableForRecovery` 方法的内部逻辑已被重构。它不再使用上述硬编码的规则，而是**完全由溯源系统的动态配置驱动**。
>
> 具体来说，它会读取 `game_config` 表中 `traceability_rules` 配置项下的 `valueConditions` 部分。
>
> **这意味着：任何在后台对“溯源配置”中“价值判断条件”的修改，都将同时、立即地影响到“物品找回系统”的入库条件。**
>
> 例如，如果管理员在溯源配置中将装备的最低记录等级从120级调整为130级，那么120-129级的装备在被出售或丢弃时，将**不会**再进入物品找回系统。
>
> **请所有管理员和开发人员在修改溯源配置时，务必意识到这一关联性。**

### 2.3 触发机制与集成点 (V2更新)

在物品从玩家背包**永久性消失**的关键位置，需要调用 `ItemRecoveryService.logDisposal()` (或类似方法) 来记录。

| 模块 | 文件/类 | 方法/场景                                               | `disposal_type` | 备注 |
| :--- | :--- |:----------------------------------------------------|:----------------| :--- |
| **NPC商店** | `org.gms.server.Shop` | `sell()`                                            | `SELL`          | **(已实现)** 在 `InventoryManipulator.removeFromSlot()` 之前调用。 |
| **玩家丢弃** | `org.gms.client.inventory.manipulator.InventoryManipulator` | `drop()`                                            | `DROP`          | **(已实现)** 在移除物品逻辑之前调用。 |
| **脚本删除** | `org.gms.scripting.AbstractPlayerInteraction` | `removeAllByInventorySlot()`, `removeAllByInventory()` | `DELETE`        | **(已实现)** 在移除物品逻辑之前调用。 |
| **卷轴失败** | `org.gms.net.server.channel.handlers.ScrollHandler` | `handlePacket()`                                    | `SCROLL_FAIL`   | **(待补充)** 当卷轴有概率会炸掉物品时，需要在物品销毁前记录。 |
| **合成失败** | `org.gms.net.server.channel.handlers.MakerSkillHandler` | `handlePacket()`                                    | `MAKER_FAIL`    | **(待补充)** 当物品制作失败且配方中的材料会消失时，需要记录这些材料。 |
| **任务消耗** | `org.gms.server.quest.Quest` | `complete()`                                        | `QUEST`         | **(待补充)** 当完成任务需要消耗物品时，记录被消耗的物品。 |

**注意**: 只有当物品是**真正消失**（而不是转移给其他玩家或系统，如交易、存仓库）时，才应该调用物品找回的记录服务。

## 3. 功能实现

### 3.1 玩家NPC找回流程

1.  **创建NPC**: 在主城设置一个“失物招领处”NPC。
2.  **后端查询**: NPC脚本调用 `ItemRecoveryService.getRecoverableItems(characterId)`。
3.  **前端展示**: NPC脚本收到DTO列表，格式化后展示给玩家。
4.  **执行找回**:
    *   玩家选择物品，点击“找回”按钮。
    *   脚本调用 `ItemRecoveryService.recoverItem(client, logId)`。
    *   后端服务执行验证、扣款、发货（通过快递）、更新状态等一系列事务操作。

### 3.2 GM后台找回流程

1.  **Web界面**: 在GM后台的玩家管理页面，增加“物品找回”功能。
2.  **API接口**:
    *   `GET /api/recovery/list/{characterId}`: 查询指定玩家的所有找回记录 (包括已过期/已找回的)。
    *   `POST /api/recovery/restore-by-gm`: GM强制为玩家恢复一件物品。
3.  **后端服务**:
    *   `ItemRecoveryService.forceRecoverItemByGm(logId)`: 跳过费用和过期检查，直接发货，并将状态置为 `RECOVERED_BY_GM`。

### 3.3 自动化清理

*   **定时任务**: `ItemRecoveryService.cleanupExpiredLogs()`
*   **触发时机**: 每日凌晨执行。
*   **逻辑**: 将超过 `recovery_deadline` 且状态为 `RECOVERABLE` 的记录更新为 `EXPIRED`。

## 5. 配置参数

| 参数名 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `item_recovery_enabled` | Boolean | `true` | 是否开启物品找回系统 |
| `item_recovery_cost_type` | Integer | `0` | 找回费用类型 (0=金币, 1=点券, 2=混合) |
| `item_recovery_base_fee_meso` | Long | `1000000` | 找回基础金币费用 |
| `item_recovery_base_fee_nx` | Long | `100000` | 找回基础点券费用 |
| `item_recovery_valuation_rate` | Double | `1.5` | 物品价值评估倍率 (基于商店售价) |
| `item_recovery_hours` | Integer | `72` | 物品可找回的时限（小时） |
| `item_recovery_expiration_days` | Integer | `7` | 物品找回记录的保留天数 |
