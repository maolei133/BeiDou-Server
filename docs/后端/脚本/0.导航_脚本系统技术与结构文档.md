# 脚本系统技术与结构文档

## 1. 概述

`BeiDou-Server-Magical` 的脚本系统是实现游戏内动态逻辑的核心，涵盖了从 NPC 对话、任务流程到大型副本事件的所有方面。该系统基于 **GraalVM JS** 引擎，采用模块化和可扩展的设计，旨在为开发者提供一个高性能、稳定且易于使用的脚本环境。

本指南将作为脚本系统的**总览文档**，对整体架构和各类脚本的实现方式进行概括。要了解每种脚本类型的详细 API 和开发范本，请点击对应的链接查阅其**详细开发指南**。

---

## 2. 架构与设计思想

### 2.1. 核心技术栈

- **脚本引擎**: **GraalVM JS**，配置为支持 **ECMAScript 2024 (ES15)** 标准。
- **Java 互操作性**: 脚本可以无缝调用 Java 代码 (`Java.type(...)`)。

### 2.2. 核心设计思想

1.  **性能与内存优化**:
    - **共享引擎 (`SHARED_ENGINE`)**: 全局单例的 GraalVM `Engine`，共享 JIT 编译器和代码缓存，大幅降低内存占用。
    - **独立上下文 (`Context`)**: 每个脚本执行时拥有独立的 `Context`，确保变量作用域隔离。
    - **客户端缓存**: 复用已编译的脚本实例，避免重复加载。

2.  **线程安全**:
    - **`SynchronizedInvocable`**: 所有脚本调用都被线程安全的包装器包裹，通过 `synchronized` 关键字解决了 GraalVM 的并发访问限制。

3.  **模块化与可扩展性**:
    - **类型分离**: 系统根据游戏内实体将脚本分为多种类型（NPC, Event, Portal 等），每种类型都有专门的管理器。
    - **统一基类 (`AbstractScriptManager`)**: 所有脚本管理器继承自此基类，复用通用逻辑。

## 4. 快速范本预览

### 4.1. NPC / 任务脚本 (NextLevel 模式)

**必须**使用此模式。通过方法路由构建对话，代码清晰易懂。

```javascript
// NPC 或 任务脚本
function start() {
    levelMain(); 
}

function levelMain() {
    // 对于任务脚本，使用 qm.sendYesNoLevel(...)
    cm.sendYesNoLevel("End", "Accept", "你好，需要我的帮助吗？");
}

function levelAccept() {
    cm.sendOkLevel("End", "很高兴能帮助你！");
}

function levelEnd() {
    cm.dispose();
}
```

### 4.2. 事件脚本 (生命周期模式)

用于复杂活动，必须正确管理生命周期和资源。

```javascript
// event/MyEvent.js
function init(eim) { /* 服务器启动时调用 */ }

function setup(difficulty, lobbyId) {
    const eim = em.newInstance("MyEvent_" + lobbyId);
    return eim; // 【必须】返回 eim
}

function playerEntry(eim, player) { /* 玩家进入时调用 */ }

function monsterValue(eim, mobId) { /* 怪物被击杀时调用 */ }

function dispose(eim) { /* 事件结束时调用，清理资源 */ }
```

### 4.3. 传送门/物品/地图/反应堆 (单函数/事件函数模式)

用于实现一次性的、非对话式的简单逻辑。

```javascript
// portal/my_portal.js
function enter(pi) {
    if (pi.getPlayer().getLevel() < 10) return false;
    pi.warp(100000000, 0);
    return true;
}

// item/1234567.js
function run(im) {
    im.gainMeso(1000);
    im.gainItem(im.getItemId(), -1);
    im.dispose();
}

// map/my_map.js
function onUserEnter(ms) {
    ms.playerMessage(5, "欢迎！");
}

// reactor/my_reactor.js
function act(rm) {
    rm.dropItems();
    rm.dispose();
}
```

## 5. 通用开发流程与最佳实践

1.  **确定脚本类型**: 根据功能需求，选择最合适的脚本类型。
2.  **查阅详细指南**: 点击上方的链接，进入对应类型的详细开发指南，了解其特定的 API 和开发模式。
3.  **使用现代语法**: 充分利用 GraalVM JS 引擎的优势，使用 ES2024 语法。
4.  **遵循设计模式**: 严格遵守各类型脚本的设计模式，特别是 NPC/任务的 NextLevel 模式和事件脚本的生命周期管理。
5.  **性能与安全**:
    - **避免阻塞**: 严禁在脚本中使用 `Thread.sleep()`。使用 `schedule` API 进行异步操作。
    - **内存安全**: 确保资源被正确释放，尤其是在事件脚本中调用 `eim.dispose()`。
6.  **日志记录**: 在关键逻辑点添加日志，便于调试。
7.  **重载脚本**: 使用 GM 命令（如 `!reloadscripts`）热重载脚本，提高开发效率。
