# 反应堆脚本开发指南

## 1. 概述

反应堆脚本 (`reactor`) 用于定义当玩家与地图上的可交互对象（即“反应堆”）进行交互时触发的逻辑。这通常用于实现宝箱、草药、矿脉、开关、陷阱等功能。

本指南将详细介绍如何编写反应堆脚本，并提供其专用的 API 接口。

---

## 2. 脚本结构与入口函数

- **存放路径**: `scripts/reactor/`
- **文件名**: 脚本的文件名必须与你在地图编辑器中为反应堆设置的脚本名称完全一致。
- **核心对象**: `rm` (`ReactorActionManager`)
- **入口函数**: 反应堆脚本必须包含一个名为 `act` 的函数。当玩家通过攻击或其他方式激活反应堆时，系统会自动调用此函数。

```javascript
/**
 * 玩家激活反应堆时执行的函数
 * @param {ReactorActionManager} rm - 反应堆脚本交互对象，提供了所有操作 API
 */
function act(rm) {
    // 在这里编写你的逻辑
    rm.dispose();
}
```

**重要提示**: 反应堆脚本是一次性执行的。执行完毕后，应调用 `rm.dispose()` 来结束脚本会话。

## 3. 开发范本

### 范本1：简单的物品掉落（宝箱）

```javascript
function act(rm) {
    // 掉落物品
    rm.dropItems();
    rm.dispose();
}
```
*注：掉落的物品列表是在数据库的 `reactordrops` 表中配置的，与反应堆的 `reactorid` 关联。`rm.dropItems()` 会根据这些配置来生成掉落物。*

### 范本2：召唤怪物

```javascript
function act(rm) {
    // 在反应堆的位置召唤 3 只 ID 为 100100 的蜗牛
    rm.spawnMonster(100100, 3);
    rm.dispose();
}
```

### 范本3：多阶段反应堆（矿脉）

矿脉或草药通常有多个状态（未采集 -> 采集一次 -> ... -> 消失）。这通过在脚本中手动“击打”反应堆来实现状态推进。

```javascript
function act(rm) {
    // 增加反应堆的 "hit" 计数
    rm.hitReactor(); 
    
    // 通常，掉落逻辑会在反应堆的最后一个阶段（即被破坏时）触发
    // 这个判断是在服务端内部根据反应堆的状态自动处理的，
    // 脚本里通常只需要调用 hitReactor() 即可。
    
    rm.dispose();
}
```

## 4. API 接口列表

### 4.1 反应堆专用 API

| 方法签名 | 返回值 | 说明 |
| :--- | :--- | :--- |
| `rm.getReactor()` | `Reactor` | 获取当前的反应堆对象实例。 |
| `rm.getPosition()` | `Point` | 获取反应堆在地图上的精确位置。 |
| `rm.hitReactor()` | `void` | 手动“击打”反应堆一次，使其状态推进。主要用于草药、矿脉等需要多次交互的反应堆。 |
| `rm.dropItems()` | `void` | 根据数据库配置掉落物品。 |
| `rm.dropItems(meso, mesoChance, minMeso, maxMeso, [minItems])` | `void` | 掉落物品，并可选择性地掉落金币。 |
| `rm.sprayItems(...)` | `void` | 以喷射的方式掉落物品（效果同 `dropItems`，但视觉上是散开的）。 |
| `rm.spawnMonster(id, [qty, pos])` | `void` | 在指定位置召唤一个或多个怪物。默认位置为反应堆位置。 |
| `rm.spawnNpc(npcId, [pos])` | `void` | 在指定位置召唤一个 NPC。默认位置为反应堆位置。 |
| `rm.killMonster(id, [withDrops])` | `void` | 杀死当前地图上所有指定 ID 的怪物。 |
| `rm.destroyNpc(npcId)` | `void` | 移除当前地图上指定 ID 的 NPC。 |

### 4.2 通用 API 参考

`rm` (`ReactorActionManager`) 对象继承自 `AbstractPlayerInteraction`，因此它拥有所有 `cm` 对象的基础 API（如 `getPlayer`, `warp`, `haveItem` 等）。
