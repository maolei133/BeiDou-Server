## 4. 当前主要类基线

### 4.1 `ResultBody`

路径：`gms-server/src/main/java/org/gms/model/dto/ResultBody.java`

现状：

- 成功工厂：`success()`、`success(T data)`、`success(SubmitBody<?> request, T data)`。
- 成功码已通过 `BizExceptionEnum.SUCCESS` 固定为 `20000`。
- 错误工厂：支持 `BaseErrorInfoInterface`、`message`、`code/message`、`HttpServletRequest` 重载。
- 会为响应填充 `responseId`；对 POST JSON 请求会读取 body 中 `requestId`。

缺口：

- 没有 `timestamp` 和 `path`。
- `error(String)` 默认 `-1`，会产生非规范业务码。
- 读取请求体失败时使用 `log.error`，此类失败更适合作为 `WARN` 或 `DEBUG`，避免业务失败构造响应时污染 `ERROR`。

### 4.2 `BizException` / `BizExceptionEnum`

路径：

- `gms-server/src/main/java/org/gms/exception/BizException.java`
- `gms-server/src/main/java/org/gms/exception/BizExceptionEnum.java`

现状：

- `BizException` 是当前业务异常类，项目没有单独的 `BusinessException` 类；后续文档中的 `BusinessException` 可映射为当前 `BizException` 或通过兼容别名迁移。
- `BizException.fillInStackTrace()` 返回自身，业务异常不填充堆栈，适合业务失败场景。
- `RequireUtil` 大量抛出 `BizExceptionEnum.ILLEGAL_PARAMETERS(40002)`。

缺口：

- 业务码与规范不一致：参数类仍是 `40002`，资源不存在是 `40004`。
- `new BizException(String)` 不设置 `errorCode`，经 `GlobalExceptionHandler` 可能返回 null code。
- 部分服务把资源不存在、参数错误、状态冲突都归入 `ILLEGAL_PARAMETERS`，需要后续按模块细分，但不应在本次基线任务大范围改业务逻辑。

### 4.3 `GlobalExceptionHandler`

路径：`gms-server/src/main/java/org/gms/exception/GlobalExceptionHandler.java`

现状：

- 捕获 `BizException`、`RuntimeException`、`ServletException`、`Exception`。
- 所有异常都调用 `logExceptionDetails`，该方法统一 `logger.error(..., e)`。
- `RuntimeException` 兜底返回 `BODY_NOT_MATCH(40000)` 和异常原文。

缺口：

- 业务异常被记录为 `ERROR`，与业务失败 `WARN/INFO` 规范冲突。
- 没有专门处理参数校验、认证失败、权限不足、资源不存在。
- 通用运行时异常不应返回 `40000`，应统一为 `50000` 并隐藏内部异常原文。
- 当前日志包含 IP、用户、路径、User-Agent，未发现 token 输出，但后续要注意不要记录 Authorization header、密码、完整请求体。

### 4.4 认证与权限异常

路径：

- `gms-server/src/main/java/org/gms/aop/AuthEntryPointJwt.java`
- `gms-server/src/main/java/org/gms/util/JwtUtils.java`
- `gms-server/src/main/java/org/gms/aop/AuthTokenFilter.java`
- `gms-server/src/main/java/org/gms/config/SpringSecurityConfig.java`

现状：

- `AuthEntryPointJwt`：已改为返回统一 JSON `code=20002`，日志 `WARN`。
- `JwtUtils.validateJwtToken`：已改为 Token 过期 `INFO`，其余 `WARN`，不再 `ERROR`。
- `AuthTokenFilter`：已改为认证异常 → 清理上下文 + `WARN`；系统异常 → `ERROR` + 向上抛。
- `SpringSecurityConfig`：已补充 `accessDeniedHandler` 配置。

缺口：

- Token 过期/无效属于可预期认证失败，应返回统一 JSON，业务码 `20002`，日志 `WARN` 或 `INFO`。
- 权限不足应返回 `30001`，日志 `WARN`。
- 认证失败不应使用 `sendError` 生成容器默认错误结构。
- 过滤器不应吞掉异常并直接关闭流；应让 Spring Security 入口或统一响应处理可控输出。
