## 2. 数据库表结构

### 2.1 `family_character`（学院关系表）

```sql
CREATE TABLE `family_character` (
    `cid`             INT NOT NULL PRIMARY KEY,
    `familyid`        INT NOT NULL,
    `seniorid`        INT NOT NULL,
    `reputation`      INT NOT NULL DEFAULT 0,     -- 当前声望
    `todaysrep`       INT NOT NULL DEFAULT 0,     -- 今日声望
    `totalreputation` INT NOT NULL DEFAULT 0,     -- 累计声望
    `reptosenior`     INT NOT NULL DEFAULT 0,     -- 贡献给上级的声望
    `precepts`        VARCHAR(200) DEFAULT NULL,  -- 学院训言（仅院长行有效）
    `lastresettime`   BIGINT NOT NULL DEFAULT 0,  -- 上次重置时间
    INDEX (cid, familyid)
);
```

### 2.2 `characters`（角色表，部分字段）

```sql
`familyId` INT NOT NULL DEFAULT -1,  -- 所属学院 ID，-1 表示无学院
```

### 2.3 `family_entitlement`（学院特权使用记录）

```sql
CREATE TABLE `family_entitlement` (
    `id`            INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    `charid`        INT NOT NULL,
    `entitlementid` INT NOT NULL,
    `TIMESTAMP`     BIGINT NOT NULL DEFAULT 0,
    INDEX (charid)
);
```

## 3. 树形架构

学院采用**二叉树**结构，每个成员最多 2 个下级（juniors）、1 个上级（senior）：

```
        院长 (seniorid=0, leader)
        ├── 晚辈A
        │   ├── 晚辈A1
        │   └── 晚辈A2
        └── 晚辈B
            ├── 晚辈B1
            └── 晚辈B2
```

**核心类关系：**

```
World ─── owns ──→ Map<Integer, Family>
                        │
Family ─── has ──→ Map<Integer, FamilyEntry> members
                        │
FamilyEntry ── senior ──→ FamilyEntry (1个上级)
            ├─ juniors[0] → FamilyEntry (下级1)
            ├─ juniors[1] → FamilyEntry (下级2)
            └─ character → Character (在线时非null)
```

**关键设计约束：**
- 每个 `Family` 由院长名称命名
- 加入/离开操作会递归影响整棵子树（`addEntryTree`/`removeEntryBranch`）
- 合并两个家族时，被合并方院长的整棵树会集体转到合并方院长之下
- `doFullCount()` 递归遍历整棵树更新世代计数

## 4. 完整交互流程

### 4.1 服务端启动

```
Server.start()
  └→ FamilyService.loadAllFamilies()
       ├→ SELECT * FROM family_character
       ├→ SELECT * FROM characters (查找角色信息)
       ├→ 创建 Family + FamilyEntry 内存对象
       ├→ 恢复树结构（处理 unmatched juniors）
       ├→ 若无院长则自动指派
       └→ doFullCount() 重新计算世代
```

### 4.2 玩家登录

```
PlayerLoggedinHandler
  ├→ chr.getFamilyId() > 0 ?
  │    ├→ wserv.getFamily(familyId) 查找内存 Family 对象
  │    ├→ family.getEntryByID(chr.getId()) 获取 FamilyEntry
  │    └→ familyEntry.setCharacter(chr) 关联在线角色
  └→ sendPacket(loadFamily / getFamilyInfo)
```

### 4.3 创建新家族（A邀请B，B接受且两人都无学院）

```
AcceptFamilyHandler
  ├→ new Family(-1, world)           // 创建新 Family 分配 ID
  ├→ new FamilyEntry(inviter → leader)
  ├→ new FamilyEntry(invitee → junior)
  ├→ invitee.setSenior(inviter, true) // 更新 DB
  ├→ insertNewFamilyRecord()         // 写 family_character
  ├→ charactersMapper.updateFamilyId() // 更新 characters.familyId
  └→ broadcast + getFamilyInfo
```

### 4.4 加入已有家族（单人加入）

```
AcceptFamilyHandler
  ├→ new FamilyEntry(inviter.getFamily(), chr)
  ├→ newEntry.setSenior(inviter.getFamilyEntry(), true)  // 更新 DB
  ├→ inviter.getFamily().addEntry(newEntry)              // 更新内存
  └→ insertNewFamilyRecord()
```

### 4.5 合并家族（院长加入另一个家族）

```
FamilyEntry.join(senior)
  ├→ TransactionTemplate（先写 DB，成功后改内存）
  │    ├→ 清除旧学院 precepts
  │    ├→ updateDBChangeFamily(cid, newFamilyId, seniorId)
  │    └→ 递归 updateNewFamilyDB(newFamilyId) 更新所有下级
  ├→ oldFamily.setMessage(null, false)    // 仅改内存
  ├→ setSenior(senior, false)             // 连接上级
  ├→ addSeniorCount()                     // 递归更新世代计数
  ├→ doFullCount()                        // 重新计算
  ├→ newFamily.addEntryTree(this)         // 整棵子树迁入新家族
  └→ world.removeFamily(oldFamily.ID)     // 旧家族从世界移除
```

### 4.6 分离（fork：成员脱离现有学院自成新院长）

```
FamilyEntry.fork()
  // DB 事务成功后才改内存（防止失同步）
  ├→ 预生成 newFamily ID
  ├→ TransactionTemplate
  │    ├→ updateDBChangeFamily(cid, newFamilyId, 0)
  │    └→ 递归 updateNewFamilyDB(newFamilyId) 更新所有下级
  ├→ family = newFamily                    // 改内存引用
  ├→ world.addFamily()                     // 注册到世界
  ├→ setSenior(null, false)               // 断开上级
  ├→ family.setLeader(this)               // 自成院长
  ├→ oldFamily.removeEntryBranch(this)    // 从旧家族移除整棵子树
  ├→ newFamily.addEntryTree(this)         // 加入新家族
  └→ doFullCount()
```

> **设计要点：** fork() 和 join() 都使用 **DB 事务前置**模式——先执行完数据库操作并通过事务提交后，才修改内存中的树结构。若事务失败，直接 return，内存状态保持不变，避免内存/DB 失同步。

### 4.7 声望变化与持久化

```
打怪/升级 → Character.levelUp()
  ├→ familyEntry.giveReputationToSenior(...)
  ├→ familyEntry.gainReputation(...)
  └→ repChanged = true         // 标记脏数据

角色保存 → Character.saveToDB()
  └→ familyEntry.saveReputation()  // 声望写入 family_character 表
```

> 声望的持久化在 `Character.saveToDB()` 末尾执行，随角色自动存盘一起写入 `family_character` 表。如果 `repChanged` 为 false 则跳过，避免无用写操作。

## 5. 已修复的 Bug 记录

以下 Bug 已在 2026-05-20 的修复中解决：

| Bug | 现象 | 根因 | 修复方式 |
|-----|------|------|----------|
| #1 声望丢失 | 重启后玩家学院声望清零 | `saveReputation()` 从未被调用，`saveAllMembersRep()` 无人调用 | `Character.saveToDB()` 末尾追加 `fe.saveReputation()` |
| #2 内存/DB失同步 | 重启后某些玩家的学院记录丢失（需重新加入） | `fork()`/`join()` 先改内存后写 DB 事务，事务失败后内存与DB不一致 | 改为 DB 事务前置（先写 DB 成功后再改内存），`updateNewFamilyDB()` 增加参数化重载 |
| #3 precepts 事务外写 | `setMessage(null, true)` 在事务外提前写入 DB，事务回滚后无法撤销 | 将 precepts 的 DB 更新移入 join() 的事务内部 |
