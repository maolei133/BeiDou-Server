# 后端架构文档

## 1. 概述

`BeiDou-Server-Magical` 的后端服务 `gms-server` 是一个基于 Java 21 和 Spring Boot 3.5.9 构建的现代化、高性能的冒险岛游戏服务端。它不仅处理核心的游戏逻辑，还通过 RESTful API 为前端管理界面提供支持。

## 2. 技术选型

- **核心框架**: Spring Boot 3.5.9
- **编程语言**: Java 21
- **构建工具**: Maven
- **Web 服务器**: Undertow (替代 Tomcat，以获得更好的性能)
- **数据库持久化**: Mybatis-Flex (一个轻量级、高性能的 ORM 框架)
- **数据库连接池**: Druid
- **数据库**: MySQL / MariaDB
- **网络通信**:
    - **游戏核心**: Netty (用于处理客户端与服务端的长连接和游戏协议)
    - **管理后台**: Spring Web (提供 RESTful API)
- **脚本引擎**: GraalVM JS (用于执行游戏内的 NPC、任务、事件等脚本)
- **安全框架**: Spring Security (用于保护管理 API)
- **API 文档**: SpringDoc OpenAPI (自动生成 Swagger UI)
- **缓存**: Caffeine (本地缓存)
- **日志**: SLF4J + Log4j2

## 3. 架构分层

项目遵循经典的分层架构模式，以实现高内聚、低耦合的设计。

```
+---------------------+
|    Controller       |  (API 层: 处理 HTTP 请求, 参数校验)
+---------------------+
        |
        v
+---------------------+
|      Service        |  (业务逻辑层: 封装核心业务, 事务管理)
+---------------------+
        |
        v
+---------------------+
|       Mapper        |  (数据访问层: 与数据库交互, CRUD 操作)
+---------------------+
        |
        v
+---------------------+
|       Model         |  (数据模型: 数据库实体, DTOs)
+---------------------+
```

### 3.1. Controller 层

- **职责**: 作为 HTTP 请求的入口，负责接收和解析来自前端的请求。
- **实现**: 使用 `@RestController` 注解。通过 `@RequestMapping`, `@GetMapping`, `@PostMapping` 等注解定义 API 端点。
- **规范**:
    - 只负责参数校验和请求转发，不包含任何业务逻辑。
    - 调用 `Service` 层来执行业务操作。
    - 捕获 `Service` 层抛出的异常，并返回统一格式的 JSON 响应。
    - 使用 SpringDoc OpenAPI 注解为 API 生成文档。

### 3.2. Service 层

- **职责**: 包含项目的核心业务逻辑。
- **实现**: 使用 `@Service` 注解。通常定义一个接口和其实现类。
- **规范**:
    - 封装复杂的业务流程，如数据处理、计算、与其他服务的交互等。
    - 通过 `@Transactional` 注解进行事务管理。
    - 依赖 `Mapper` 层进行数据持久化。
    - 遇到业务错误时，应抛出自定义的业务异常。

### 3.3. Mapper 层

- **职责**: 数据访问层，负责与数据库进行直接交互。
- **实现**: 使用 Mybatis-Flex 的 `BaseMapper` 接口。
- **规范**:
    - 定义继承自 `BaseMapper<Entity>` 的接口。
    - Mybatis-Flex 会自动实现常规的 CRUD 操作。
    - 对于复杂查询，可以使用 `@Select` 注解或 XML 文件编写 SQL。

### 3.4. Model 层

- **职责**: 定义数据结构。
- **分类**:
    - **实体 (Entity)**: 与数据库表一一对应，使用 Mybatis-Flex 的 `@Table` 注解。
    - **数据传输对象 (DTO)**: 用于在不同层之间，特别是 `Controller` 和 `Service` 层之间传输数据。

## 4. 核心模块

### 4.1. 游戏网络模块 (Netty)

- **职责**: 处理游戏客户端的 TCP 长连接。
- **流程**:
    1.  **启动**: 服务启动时，初始化 Netty Server。
    2.  **连接**: 客户端连接后，创建 `Channel` 并绑定一个 `Player` 会话。
    3.  **编解码**: 使用自定义的 `Encoder` 和 `Decoder` 来处理游戏协议的封包和解包。
    4.  **分发**: `Handler` 根据包头 (Opcode) 将请求分发到对应的处理器进行处理。

### 4.2. 脚本引擎模块 (GraalVM JS)

- **职责**: 执行和管理游戏内的 JavaScript 脚本。
- **实现**:
    - `AbstractScriptManager`: 脚本管理的基类，负责加载、缓存和执行脚本。
    - `EventInstanceManager`: 管理事件脚本的实例，如副本、计时器等。
- **优势**: GraalVM 提供了比传统 Nashorn 引擎更好的性能和更完善的 ES6+ 支持。

### 4.3. 安全模块 (Spring Security)

- **职责**: 保护管理后台的 RESTful API。
- **实现**:
    - 使用 JWT (JSON Web Token) 进行无状态认证。
    - 用户登录成功后，颁发一个包含用户信息的 Token。
    - 后续请求在 Header 中携带此 Token，通过一个 `Filter` 进行验证和授权。

## 5. 数据库设计

- **ORM**: Mybatis-Flex
- **迁移**: Flyway (用于管理数据库版本和 schema 变更)
- **原则**:
    - 每个实体对应一个 `Mapper` 接口。
    - 遵循数据库设计范式，合理使用索引以优化查询性能。

## 6. 配置与环境

- **配置文件**: `application.yml`
- **多环境支持**: 通过 Spring Profiles (如 `application-dev.yml`, `application-prod.yml`) 来管理不同环境的配置。
- **日志配置**: `log4j2-spring.xml`

通过这种架构，`gms-server` 实现了清晰的职责分离、良好的可扩展性和可维护性，为游戏的稳定运行和未来的功能迭代奠定了坚实的基础。
