# 内置辅助插件开发指南

## 1. 概述

`gms-server` 项目中的 `org.gms.client.cheatsystem` 模块提供了一个可扩展的内置辅助（作弊检测/功能增强）插件系统。该系统旨在允许开发者以模块化的方式添加、管理和控制各种游戏内辅助功能，同时提供统一的生命周期管理、日志记录和配置机制。

本指南将详细介绍 `cheatsystem` 模块的架构、核心组件及其职责，并提供开发新辅助插件的详细步骤和最佳实践。

## 2. 模块架构与核心组件

`cheatsystem` 模块采用插件化设计，核心思想是将具体的功能实现与管理逻辑解耦。

### 2.1. 核心目录结构

```
cheatsystem/
├── core/                   # 核心接口、抽象类和工厂
│   ├── CheatPlugin.java        # 插件接口
│   ├── CheatManager.java       # 插件生命周期管理器
│   ├── BaseCheatPlugin.java    # 插件抽象基类
│   └── CheatPluginFactory.java # 插件注册与创建工厂
├── plugin/                 # 具体插件实现
│   ├── example/
│   │   └── ExampleCheatPlugin.java # 示例插件
│   ├── MobVacPlugin.java           # 吸怪插件
│   └── ItemVacPlugin.java          # 吸物插件
├── manager/                # 模块级管理器
│   └── CheatModuleManager.java # 作弊模块的整体管理器
└── README.md               # 模块说明文档
```

### 2.2. 核心组件职责

#### 2.2.1. `CheatPlugin` (接口)

- **路径**: `org.gms.client.cheatsystem.core.CheatPlugin`
- **职责**: 定义了所有内置辅助插件必须实现的基本行为和生命周期方法。
- **关键方法**:
    - `getName()`: 获取插件的唯一名称。
    - `getDescription()`: 获取插件的描述信息。
    - `initialize(Character player)`: 插件初始化方法，传入玩家对象。
    - `start()`: 启动插件。
    - `start(Map<String, Object> parameters)`: 带参数启动插件（默认实现调用无参 `start()`）。
    - `stop()`: 停止插件。
    - `isRunning()`: 检查插件是否正在运行。
    - `updateConfig()`: 更新插件配置。

#### 2.2.2. `BaseCheatPlugin` (抽象基类)

- **路径**: `org.gms.client.cheatsystem.core.BaseCheatPlugin`
- **职责**: 提供了 `CheatPlugin` 接口的默认实现和通用功能，简化了新插件的开发。
- **关键特性**:
    - **玩家对象**: 存储 `Character player` 对象，方便插件访问玩家数据和执行玩家相关操作。
    - **运行状态**: 管理 `running` 状态。
    - **日志**: 集成 `AuditLogger`，提供 `logPluginOperationAuto`, `logPluginActivationAuto` 等日志记录方法，确保插件操作可追溯。
    - **扩展值**: 提供 `getExtendValue`, `saveOrUpdateExtendValue` 等方法，方便插件与数据库中的账号/角色扩展值进行交互，实现数据持久化（如使用次数、配置等）。
    - **启动参数**: 支持通过 `start(Map<String, Object> parameters)` 接收参数，并提供 `getStartParameter` 系列方法方便获取参数。
    - **生命周期钩子**: 提供 `onStart()` 和 `onStop()` 抽象方法，子类只需重写这两个方法即可实现具体的启动和停止逻辑。

#### 2.2.3. `CheatManager` (插件生命周期管理器)

- **路径**: `org.gms.client.cheatsystem.core.CheatManager`
- **职责**: 负责管理单个玩家的所有 `CheatPlugin` 实例的生命周期。每个 `Character` 对象都会拥有一个 `CheatManager` 实例。
- **关键方法**:
    - `registerPlugin(CheatPlugin plugin)`: 注册插件，并调用其 `initialize()` 方法。
    - `unregisterPlugin(String pluginName)`: 注销插件，并调用其 `stop()` 方法。
    - `getPlugin(String pluginName)`: 根据名称获取插件实例。
    - `startAllPlugins()`: 启动所有已注册的插件。
    - `stopAllPlugins()`: 停止所有已注册的插件。
    - `updateAllConfig()`: 更新所有插件的配置。
- **日志**: 记录 `CheatManager` 自身的关键操作。

#### 2.2.4. `CheatPluginFactory` (插件注册与创建工厂)

- **路径**: `org.gms.client.cheatsystem.core.CheatPluginFactory`
- **职责**: 静态工厂类，负责集中注册所有可用的 `CheatPlugin` 类型，并根据名称创建插件实例。
- **关键特性**:
    - **`pluginRegistry`**: 静态 `Map` 存储插件名称到 `Supplier<CheatPlugin>` 的映射，实现延迟加载。
    - **`static` 初始化块**: 在类加载时自动注册预定义的插件（如 `ItemVacPlugin`, `MobVacPlugin`）。
    - `registerPlugin(String name, Supplier<CheatPlugin> supplier)`: 注册新的插件类型。
    - `createPlugin(String name)`: 根据插件名称创建新的 `CheatPlugin` 实例。
    - `getRegisteredPlugins()`: 获取所有已注册插件的名称。

#### 2.2.5. `CheatModuleManager` (作弊模块的整体管理器)

- **路径**: `org.gms.client.cheatsystem.manager.CheatModuleManager`
- **职责**: 负责管理整个作弊检测模块的全局行为，例如在玩家登录时创建 `CheatManager` 实例，在玩家离线时销毁等。它可能是一个单例或由 Spring 管理的组件。

## 3. 开发新辅助插件的步骤

开发一个新的辅助插件需要遵循以下步骤，以确保其能无缝集成到现有系统中。

### 3.1. 步骤一：定义插件功能与名称

- **确定插件名称**: 选择一个唯一且描述性的名称（例如 `AutoAttack`, `SpeedHackDetect`）。这将是插件的 `getName()` 方法的返回值，也是在 `CheatPluginFactory` 中注册的键。
- **确定插件描述**: 编写插件的简要描述。

### 3.2. 步骤二：创建插件类并继承 `BaseCheatPlugin`

- 在 `org.gms.client.cheatsystem.plugin` 包下（或其子包）创建一个新的 Java 类，例如 `MyNewCheatPlugin.java`。
- 让该类继承 `BaseCheatPlugin`。

```java
package org.gms.client.cheatsystem.plugin;

import org.gms.client.cheatsystem.core.BaseCheatPlugin;
import org.gms.client.Character; // 根据需要导入

public class MyNewCheatPlugin extends BaseCheatPlugin {

    // 插件特有的成员变量和配置

    public MyNewCheatPlugin() {
        super();
        // 可以在这里进行插件特有的初始化
    }

    @Override
    public String getName() {
        return "MyNewCheat"; // 替换为你的插件名称
    }

    @Override
    public String getDescription() {
        return "这是一个新的辅助插件示例。"; // 替换为你的插件描述
    }

    // 可选：重写 initialize 方法，进行插件特有的初始化逻辑
    @Override
    public void initialize(Character player) {
        super.initialize(player); // 必须调用父类方法
        // 加载插件特有配置，例如从 GameConfig 或数据库
        // loadMyPluginConfig();
    }

    // 可选：重写 updateConfig 方法，用于运行时更新配置
    @Override
    public void updateConfig() {
        // 重新加载插件特有配置
        // loadMyPluginConfig();
    }

    @Override
    protected void onStart() {
        super.onStart(); // 必须调用父类方法
        // 在这里实现插件启动时的核心逻辑
        logPluginOperationAuto(getName() + " 插件已启动。");
        // 例如：启动定时任务、监听游戏事件等
    }

    @Override
    protected void onStop() {
        super.onStop(); // 必须调用父类方法
        // 在这里实现插件停止时的清理逻辑
        logPluginOperationAuto(getName() + " 插件已停止。");
        // 例如：取消定时任务、移除事件监听器等
    }

    // 插件特有的业务方法
    public void doMyPluginSpecificAction() {
        if (isRunning() && player != null) {
            player.dropMessage(5, "我的新插件正在执行特定操作！");
            logPluginUsage("执行了特定操作");
        }
    }
}
```

### 3.3. 步骤三：实现核心逻辑 (`onStart()` 和 `onStop()`)

- **`onStart()`**:
    - 在此方法中编写插件启动时需要执行的所有逻辑。
    - 可以从 `getStartParameters()` 获取启动参数，根据参数调整插件行为。
    - 启动任何必要的定时任务（使用 `TimerManager`）。
    - 注册游戏事件监听器。
    - 进行必要的检查（如玩家状态、地图条件等）。
    - 使用 `logPluginActivationAuto()` 记录插件启动日志。
- **`onStop()`**:
    - 在此方法中编写插件停止时需要执行的所有清理逻辑。
    - 取消所有启动的定时任务。
    - 移除所有注册的事件监听器。
    - 清理任何资源或状态。
    - 使用 `logPluginDeactivation()` 记录插件停止日志。

### 3.4. 步骤四：利用 `BaseCheatPlugin` 提供的工具方法

- **日志记录**:
    - `logPluginOperationAuto(String message)`: 记录插件的通用操作信息。
    - `logPluginActivationAuto(String message)`: 记录插件激活信息。
    - `logPluginDeactivation(String reason)`: 记录插件停用信息。
    - `logPluginUsage(String details)`: 记录插件使用详情。
- **扩展值操作**:
    - `getAccountExtendValue(int accountId, String extendType, String extendName)`: 获取账号扩展值。
    - `saveOrUpdateAccountExtendValue(int accountId, String extendType, String extendName, String extendValue)`: 保存或更新账号扩展值。
    - 类似的方法也适用于角色 (`Character`)。
- **获取启动参数**:
    - `getStartParameters()`: 获取所有启动参数。
    - `getStartParameterAsString(String key, String defaultValue)`: 获取字符串类型参数。
    - `getStartParameterAsInt(String key, int defaultValue)`: 获取整数类型参数。
    - `getStartParameterAsBoolean(String key, boolean defaultValue)`: 获取布尔类型参数。

### 3.5. 步骤五：在 `CheatPluginFactory` 中注册插件

- 打开 `org.gms.client.cheatsystem.core.CheatPluginFactory.java` 文件。
- 在 `static` 初始化块中，使用 `registerPlugin` 方法注册你的新插件。

```java
// CheatPluginFactory.java
static {
    // 注册所有插件
    registerPlugin("ItemVac", ItemVacPlugin::new);
    registerPlugin("MobVac", MobVacPlugin::new);
    // 注册你的新插件
    registerPlugin("MyNewCheat", MyNewCheatPlugin::new); // 确保 MyNewCheatPlugin 有无参构造函数
}
```

### 3.6. 步骤六：在 `CheatModuleManager` 中集成 (如果需要)

- `CheatModuleManager` 负责在适当的时机（例如玩家登录时）为玩家创建 `CheatManager` 实例，并注册所有可用的插件。
- 确保 `CheatModuleManager` 会调用 `CheatPluginFactory.createPlugin()` 来创建你的插件实例，并通过 `CheatManager.registerPlugin()` 进行注册。通常，这会遍历 `CheatPluginFactory.getRegisteredPlugins()` 来注册所有插件。

## 4. 示例：一个简单的消息插件

假设我们想创建一个插件，在玩家启动时发送一条欢迎消息。

```java
package org.gms.client.cheatsystem.plugin;

import org.gms.client.cheatsystem.core.BaseCheatPlugin;
import org.gms.client.Character;

public class WelcomeMessagePlugin extends BaseCheatPlugin {

    public WelcomeMessagePlugin() {
        super();
    }

    @Override
    public String getName() {
        return "WelcomeMessage";
    }

    @Override
    public String getDescription() {
        return "在玩家启动时发送欢迎消息。";
    }

    @Override
    protected void onStart() {
        super.onStart();
        if (player != null) {
            String message = getStartParameterAsString("message", "欢迎使用内置辅助系统！");
            player.dropMessage(5, message);
            logPluginOperationAuto("向玩家 " + player.getName() + " 发送了欢迎消息: " + message);
        }
    }

    @Override
    protected void onStop() {
        super.onStop();
        logPluginOperationAuto("WelcomeMessage 插件已停止。");
    }
}
```

**在 `CheatPluginFactory.java` 中注册:**

```java
// CheatPluginFactory.java
static {
    // ... 其他插件注册
    registerPlugin("WelcomeMessage", WelcomeMessagePlugin::new);
}
```

**使用示例 (在 `CheatManager` 或其他地方):**

```java
// 假设在某个玩家登录时
CheatManager cheatManager = new CheatManager(player);
cheatManager.registerPlugin(CheatPluginFactory.createPlugin("WelcomeMessage"));
// 启动时可以传入参数
Map<String, Object> params = new HashMap<>();
params.put("message", "尊敬的 " + player.getName() + "，欢迎来到冒险岛世界！");
cheatManager.getPlugin("WelcomeMessage").start(params);
```

## 5. 注意事项与最佳实践

- **职责单一**: 每个插件应专注于一个特定的辅助功能或检测逻辑。
- **性能**: 插件中的逻辑应尽可能高效，避免阻塞游戏主线程。特别是定时任务，要确保其执行时间短。
- **游戏平衡性**: 任何辅助功能都可能影响游戏平衡。在设计和实现时，务必考虑其对游戏环境的影响。
- **日志记录**: 充分利用 `BaseCheatPlugin` 提供的日志方法，记录插件的启动、停止、关键操作和异常，便于调试和审计。
- **错误处理**: 插件内部应妥善处理异常，避免因插件错误导致整个服务端崩溃。
- **配置化**: 插件的关键参数应支持配置化（例如通过 `GameConfig` 或数据库），方便运行时调整。
- **线程安全**: 如果插件涉及多线程操作，务必考虑线程安全问题。
- **资源清理**: 在 `onStop()` 方法中，务必清理所有占用的资源，如定时任务、监听器等，防止内存泄漏。
- **玩家状态检查**: 在执行任何玩家相关操作前，始终检查 `player` 对象是否为空，以及玩家是否在线 (`player.isLoggedInWorld()`)。
- **地图条件检查**: 对于地图相关的辅助功能，需要仔细检查地图的类型、事件、Boss等条件，避免在不适用的地图上运行。
