### 1.2 IP 双字段模型

```
                    ┌─────────────────────────────┐
                    │         Client               │
                    │                              │
  channelActive()──▶│ effectiveAddress = TCP 对端IP │──▶ getEffectiveAddress()
                    │          (永不改变)          │       仅 getInetSocket() 用
                    │                              │
  Proxy Protocol ──▶│ remoteAddress = 覆盖为真实IP  │──▶ getRemoteAddress()
  仅可信来源        │          (可被覆盖)          │       25+ 处调用方
                    └─────────────────────────────┘

  getInetSocket() 路由逻辑:
    remoteAddress ≠ effectiveAddress  →  代理模式  →  返回 Channel.ip (wanHost)
    remoteAddress ＝ effectiveAddress  →  直连模式  →  local? → localhost
                                                       lan?   → lanHost
                                                       else   → wanHost
```

### 1.3 涉及的类与职责

| 类 | 职责 |
|----|------|
| `Client` | 持有 `remoteAddress`(业务IP) + `effectiveAddress`(物理IP)，双字段 JSDOC |
| `Server` | `getInetSocket()` 代理检测 + local/LAN 路由；过渡逻辑已全量迁出 |
| `TransitionSession` | 跨连接数据 POJO，携带 accountId/accountName/charId/macs/hwid 等 |
| `LoginCoordinator` | 单例，管理 TransitionSession 生命周期：prepare/consume/release/purge |
| `PlayerLoggedinHandler` | 55 行 orchestrator + 9 个私有方法 |
| `ServerChannelInitializer` | Proxy Protocol v2 自定义 handler + 可信来源白名单 |
| `SessionCoordinator` | `closeSession(null)` 保护；`fetchInTransitionSessionClient` 改用 LoginCoordinator |

## 三、Proxy Protocol 设计细节

### 3.1 Pipeline 位置

```
pipeline.addLast(自定义 Proxy handler)   ← 最前端
pipeline.addLast(IdleStateHandler)
pipeline.addLast(PacketCodec)
pipeline.addLast(Client)
```

### 3.2 决策树

```
首包到达
  │
  ├─ readableBytes < 16 ──────────▶ 直连，透传，自移除
  │
  ├─ 首 12 字节 ≠ v2 签名 ────────▶ 直连，透传，自移除
  │
  ├─ version≠2 或 command≠1 ──────▶ WARN，透传，自移除
  │
  ├─ addrLen > readableBytes ─────▶ WARN，透传，自移除
  │
  ├─ 物理 IP 非可信来源 ──────────▶ WARN，忽略 Proxy 头，透传
  │
  ├─ family=0x11 (IPv4) ──────────▶ 解析源 IP，覆盖 remoteAddress，透传
  │
  └─ family=0x21 (IPv6) ──────────▶ WARN（暂不支持），透传
```

### 3.3 可信来源

```java
static {
    TRUSTED_PROXY_IPS.add("127.0.0.1");           // 本机
    collectLocalLanIps();                          // 枚举网卡 RFC1918 内网 IP
    // 后续接入: GameConfig.getServerString("proxy.trusted.sources")
}
```

## 四、Transition 生命周期

```
  CharSelectedHandler                    PlayerLoggedinHandler
  (登录服)                               (频道服)
      │                                       │
      │ LoginCoordinator.prepare(c, cid)      │
      │  → 创建 TransitionSession             │
      │  → key = remote:charId                │
      │  → 存入 pendingTransitions             │
      │                                       │
      │──── getServerIP(IP:port) ────────────▶│ 客户端收到频道地址
      │                                       │
      │                                       │ LoginCoordinator.consume(c, cid)
      │                                       │  → 取出 + 校验 charId
      │                                       │  → 删除 (原子)
      │                                       │  → session.applyTo(c)
      │                                       │    回填: accId/name/macs/hwid/
      │                                       │          slots/language
      │                                       │
      │                                       │ 正常登录流程...
      │  (客户端断开登录连接)                   │
      │                                       │
      │  LoginCoordinator.release(accId)      │  ← 异常清理
      │                                       │
      │  LoginCoordinator.purgeExpired(60s)   │  ← 定时清理
```

## 五、回归验证矩阵

| # | 场景 | Proxy Protocol | 期望 |
|---|------|:---:|------|
| T1 | 直连 | N/A | `remoteAddress`=`effectiveAddress`=真实IP，登录正常 |
| T2 | FRP + PRP v2 (可信) | ✅ | `remoteAddress`=真实IP，`effectiveAddress`=FRP IP |
| T3 | FRP + PRP v2 (非可信) | ✅ | WARN，忽略 Proxy 头，`remoteAddress`不变 |
| T4 | FRP 无 PRP | ❌ | `remoteAddress`=`effectiveAddress`=FRP IP (降级) |
| T5 | 同 IP 双账号并发 | ✅/❌ | PRP 开启时不串号；无 PRP 时降级 |
| T6 | 五个选角入口 | N/A | 全部通过 LoginCoordinator，migration 一致 |
